## 1. Directory Layout
Templates live in the `execution/templates/assets/` directory.

```text
execution/templates/assets/
└── [tech_stack]/           (e.g., fastapi, react, postgres)
    └── v[version]/         (e.g., v1)
        ├── manifest.json   (Metadata about the template)
        ├── src/            (Template source files)
        └── tests/          (Template tests)
```

## 2. Template Manifest (`manifest.json`)
Every template version MUST include a `manifest.json`.
```json
{
  "name": "fastapi-backend",
  "version": "1.0",
  "compatibility": ["python>=3.11"],
  "required_variables": ["project_name", "api_port", "database_url"],
  "entrypoint": "main.py"
}
```

## 3. Variables
Variables are injected into templates via Jinja2 syntax (e.g., `{{ project_name }}`).
Standard variables:
- `project_name`: Slugified project name.
- `project_description`: Brief description from the PRD.
- `database_url`: Computed connection string.
- `api_port`: Assigned port.

## 4. Versioning
Templates are versioned explicitly in the folder path (e.g., `v1`, `v2`). The `tech-stack.json` generated by the Engineering Brain dictates the template version to prevent breaking changes when updates occur.

## 5. Compatibility
Templates must document their dependencies (Node versions, Python versions) within the manifest to ensure the Validation Engine provisions the correct environment.
